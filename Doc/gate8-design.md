# Gate 8 Design - Artifact/schema/tool-contract normalization

> Scope: Gate 8 of `Doc/post-gate6-roadmap.md`. Gate 7 proved a second bug
> family. Gate 8 does not add gameplay behavior. It stabilizes the shared
> artifacts that Gate 9 orchestration will pass between tools.

## Goal

Make the outputs from Gates 3-7 machine-checkable as contracts:

```text
Unity/tool run -> run_result
Gameplay Agent -> bug_report
VLM/evidence helper -> visual_evidence
Spec-to-Test -> test_plan_ir
Bug-to-Regression -> regression_plan_ir
CLI wrapper -> tool_result
```

Gate 9 can then orchestrate existing tools without guessing JSON shapes or
parsing prose logs. PASS/FAIL remains owned by the existing CLI tools and Unity
test runner; schemas only check artifact shape and required evidence fields.

## Non-Goals

- No new Unity mechanics, scenes, bugs, or bug toggles.
- No multi-agent orchestration, LangGraph coordinator, RAG, or CI dashboard.
- No coverage or general mutation framework.
- No change to the v1 Python agent core.
- No new package dependency just to validate schemas. Use the Python standard
  library unless a dependency already exists in both system Python and `.venv`.

## Artifacts to Normalize

Gate 8 validates these existing artifact families:

| Artifact | Latest local example | Schema |
|---|---|---|
| Unity run result | `results/unity/results.xml` parsed to a normalized JSON object | `schemas/run_result.schema.json` |
| Gameplay bug report | `results/unity/gate6_source_agent_report.json`, `results/unity/gate7_presentation_bug_report.json` | `schemas/bug_report.schema.json` |
| Visual evidence | `results/unity/vlm_evidence_report.json` and embedded Gate 7 evidence | `schemas/visual_evidence.schema.json` |
| Test Plan IR | `results/unity/spec_to_test_plan.json` | `schemas/test_plan_ir.schema.json` |
| Regression Plan IR | `results/unity/bug_to_regression_plan.json`, `results/unity/gate7_presentation_regression_plan.json` | `schemas/regression_plan_ir.schema.json` |
| CLI tool result | the validator's own normalized summary object | `schemas/tool_result.schema.json` |

Each schema also gets at least one committed golden fixture under
`tests/fixtures/artifacts/`.

## Schema Rules

1. Schemas describe the current contract; they do not redesign artifacts during
   Gate 8.
2. Fields used by one gate only are optional unless a later consumer already
   needs them.
3. Evidence-critical fields are required:
   - bug reports require `status`, `failure_type`, `goal`, `debug_state`,
     `screenshot_path`, and `trace`;
   - visual evidence requires `schema_version`, `verdict_source`,
     `visual_evidence_role`, and `questions`;
   - plans require `plan_id` and non-empty `cases`.
4. `visual_evidence_role` must remain `supporting_evidence_only`.
5. `failure_type` may be `progression_softlock`, `presentation_mismatch`, or
   `null` for a success report. Gate 8 does not expand the taxonomy.
6. Schemas should allow additive fields so later gates can extend artifacts
   without breaking older consumers.

## Validator Smoke

Add:

```text
scripts/validate_gate_artifacts.py
```

The script must:

1. validate all committed golden fixtures;
2. validate the latest local artifacts in `results/unity/`;
3. parse Unity NUnit XML into a normalized `run_result` object;
4. validate its own final `tool_result` summary object;
5. print `PASS ...` / `FAIL ...`;
6. exit non-zero on any validation failure.

Because `jsonschema` is not installed in either system Python or `.venv`, the
validator implements only the JSON Schema subset this repo needs:

- `type`
- `required`
- `properties`
- `items`
- `enum`
- `const`
- `anyOf`
- `minimum`
- `additionalProperties`

This is intentionally small. If Gate 9 needs richer schema behavior, it can add
a dependency after the current contract is proven useful.

## Golden Fixtures

Committed fixtures should be small and stable. Prefer relative paths and short
traces over machine-specific absolute paths. Golden fixtures are not the source
of runtime truth; they protect schema drift and make the validator runnable even
before a fresh Unity run creates `results/unity/`.

Minimum fixtures:

```text
tests/fixtures/artifacts/
  gate3_progression_softlock_report.json
  gate5_visual_evidence.json
  gate6_regression_plan.json
  gate7_presentation_mismatch_report.json
  gate7_regression_plan.json
  gate4_test_plan.json
  unity_playmode_run_result.json
  validate_artifacts_tool_result.json
```

## PASS Criteria

1. `python scripts/validate_gate_artifacts.py` prints PASS/FAIL and exits 0.
2. The validator covers the latest Gate 3/5/6/7 artifacts generated by the
   existing smokes.
3. Each schema has at least one golden fixture.
4. Existing gate checks remain green:
   - `python scripts/run_unity_tests.py`
   - `python scripts/unity_smoke.py`
   - `python scripts/unity_agent_smoke.py`
   - `python scripts/spec_to_test_smoke.py`
   - `python scripts/vlm_evidence_smoke.py`
   - `python scripts/bug_to_regression_smoke.py`
   - `python scripts/presentation_bug_smoke.py`
5. v1 baseline remains green:
   `.venv\Scripts\python.exe -m pytest --basetemp .pytest_tmp\gate8-v1`.

## Implementation Notes

- Use current artifact field names. Do not rename existing outputs in Gate 8.
- Keep schema validation separate from runtime verdicts. A valid bug report can
  still describe a failing Unity run; the smoke decides whether that failure is
  expected.
- If a local artifact is missing, the validator should report it as a missing
  latest artifact in default mode. A `--fixtures-only` mode may validate only
  committed golden fixtures for documentation/CI bootstrap.
- Do not commit `results/unity/`; keep runtime artifacts local and ignored.

## Gate 9 Handoff

Gate 9 should consume these contracts as the state passed between orchestration
nodes. It should call the existing tools and read their artifacts; it should not
replace Unity CLI, smoke scripts, or schema validation as the source of truth.
